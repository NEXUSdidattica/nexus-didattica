Anatomia del Web: URI, URL e URN

Differenze strutturali tra URI, URL e URN, analisi dettagliata dei componenti di un indirizzo e simulatore di scomposizione.

1. Le definizioni fondamentali: URI, URL e URN

Nel contesto delle reti e del World Wide Web, l'identificazione delle risorse avviene tramite standard precisi definiti dal W3C e dall'IETF. Spesso i termini vengono confusi, ma esiste una precisa relazione gerarchica tra di essi:

Acronimo Nome Completo Descrizione e Scopo
URI Uniform Resource Identifier Stringa di caratteri che identifica univocamente una risorsa astratta o fisica. È il termine generale che comprende sia URL che URN.
URL Uniform Resource Locator Un sottoinsieme di URI che non solo identifica una risorsa, ma specifica anche come accedervi (il protocollo di rete) e dove si trova (la posizione di rete).
URN Uniform Resource Name Un sottoinsieme di URI che identifica una risorsa per nome all'interno di un determinato spazio, indipendentemente dalla sua posizione fisica (es. ISBN per i libri).
La Relazione Logica:

"Ogni URL è un URI, ma non tutti gli URI sono URL." (Un URN è un URI ma non specifica una posizione o un protocollo di accesso).

2. Anatomia Dettagliata di un URL

Un URL standard è composto da diverse parti ben distinte che guidano il browser nell'individuazione e nel contatto con il server di destinazione:

https://www.nexusdidattica.it:443/materie/informatica.html?corso=reti#sezione-2
    Protocollo / Schema (es. https://): Specifica il protocollo applicativo da utilizzare per la comunicazione (es. HTTP, HTTPS, FTP, MAILTO).
    Dominio / Host (es. www.nexusdidattica.it): L'indirizzo simbolico associato all'indirizzo IP del server autoritativo tramite il sistema DNS.
    Porta (es. :443): Il canale logico di comunicazione sul server (opzionale se si usano le porte standard come 80 per HTTP e 443 per HTTPS).
    Percorso / Path (es. /materie/informatica.html): La struttura delle cartelle e il nome del file specifico richiesto sul server.
    Query String (es. ?corso=reti): I parametri di richiesta passati al server sotto forma di coppie chiave-valore, separati dal carattere ? e uniti da &.
    Frammento / Anchor (es. #sezione-2): Un puntatore interno che indica una specifica sezione o ancora all'interno della pagina web caricata.

3. Simulatore Interattivo: Scompositore di URL (URL Parser)

Inserisci o seleziona un URL di test per analizzarne e scomporre in tempo reale tutte le singole componenti strutturali.

url-parser@nexus-sys:~# URL Component Analyser
> Seleziona un URL e avvia la scomposizione per visualizzare protocollo, host, percorso e parametri.
